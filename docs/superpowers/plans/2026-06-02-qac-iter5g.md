# qac iter-5g — FLCC per-BMN signal + evaluation-unit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move `rlcc_action_probe`'s per-BMN signal from RLCC (`rlcc_state_completed`) to FLCC (`flcc_node_state`), classify each tray (failed / ignorable / success / in-progress) so terminal trays leave the pool, bound the walk with `step.Timeout`, and record per-BMN FLCC evidence tagged with an `evaluation_unit` — all gatherer-only (no verdict).

**Architecture:** Add `QueryFLCCState` to `lifecycleclient` (map + prom backends, like the existing `QueryActionState`). Add a pure classifier in the probe package. Rewrite the probe's poll loop to use the FLCC signal + classifier + terminal-exit, recording the raw observation per CT. Add a `step.Timeout` backstop in the engine runner. Tag the canonical `l11_fielddiag` step with `evaluation_unit: nvlink-domain`.

**Tech Stack:** Go 1.23 (bare module `qac`), `modernc.org/sqlite`, event-sourced store, `net/http`. Spec: `docs/superpowers/specs/2026-06-02-qac-iter5g-design.md`.

## Key facts discovered during planning (read first)

1. **The metric is `flcc_node_state`** (emitted by fleet-lifecycle-controller's own exporter), keyed by a **`device_slot`** label — so the probe queries by deviceslot directly, no rack/node parsing. Labels we read: `state`, `step`, `prev_state`, `prev_step`, `workflow`. Real sample: `flcc_node_state{device_slot="b2-r011-node02", state="fail", step="test", prev_state="test", workflow="provision"}`.
2. **Fail = `state == "fail"`** (generic); `step`/`prev_step` says which phase. Ignore set = states `rma`/`broken`/`debug`/`dev` OR workflow `broken-collect`. These are the certain, load-bearing buckets. `success_state` is optional and left **unset** on the canonical template this iter (the precise L11 success criterion is iter-5h).
3. **The probe today** (`internal/probe/rlccactionprobe/rlccactionprobe.go`) polls `c.LifecycleClient.QueryActionState(...)` each tick (loop around lines 137–163), marks completed CTs, writes per-CT evidence via `writeCTEvidence`, and aggregates via `summarize`. iter-5g replaces the *poll + classify* portion; `buildPool` and the RLCC-ignore re-detection block are unchanged.
4. **MapClient pattern** (`internal/lifecycleclient/mapclient.go`): a deterministic in-memory `Client` with per-key tick counters and `Set...` overrides for tests. We mirror it for `QueryFLCCState`.
5. **The engine runner** (`internal/engine/runner.go:144`) calls `p.Run(ctx, ...)` with `ctx == context.Background()` (from `runOnce`), deliberately not the request ctx. `step.Timeout` (a `time.ParseDuration` string on `template.Step.Timeout`) is referenced nowhere — iter-5g wires it as a server-side backstop.
6. **The iter-5f e2e test** `TestCanonicalCanary_RLCCActionProbe_EndToEnd` (`internal/api/canonical_integ_test.go`) seeds completion via the MapClient `QueryActionState` 3-tick default and asserts `count_active/count_completed`. iter-5g rewrites it to seed FLCC observations and assert the new bucket counts.

// QueryFLCCState satisfies Client. Fans out one instant query per
// deviceslot against flcc_node_state and reads the lifecycle labels off
// the (at most one) returned series. A deviceslot with no series yields a
// zero-value FLCCObservation.
func (c *PromClient) QueryFLCCState(ctx context.Context, deviceslots []string) (map[string]FLCCObservation, error) {
	out := make(map[string]FLCCObservation, len(deviceslots))
	for _, ds := range deviceslots {
		samples, err := c.queryVector(ctx, renderFLCCStateQuery(ds))
		if err != nil {
			return nil, fmt.Errorf("query flcc state %s: %w", ds, err)
		}
		if len(samples) == 0 {
			out[ds] = FLCCObservation{}
			continue
		}
		m := samples[0].Metric
		out[ds] = FLCCObservation{
			State:     m["state"],
			Step:      m["step"],
			PrevState: m["prev_state"],
			PrevStep:  m["prev_step"],
			Workflow:  m["workflow"],
		}
	}
	return out, nil
}
```

package rlccactionprobe

import "qac/internal/lifecycleclient"

// ctOutcome is the per-CT classification of an FLCC observation.
type ctOutcome string

const (
	outcomeSuccess    ctOutcome = "success"
	outcomeFailed     ctOutcome = "failed"
	outcomeIgnorable  ctOutcome = "ignorable"
	outcomeInProgress ctOutcome = "in_progress"
)

// flccIgnorableStates are FLCC states that take a node out of the normal
// production lifecycle (pulled / RMA / under debug). A CT in one of these
// is dropped from the pool and excluded from any verdict. Source: wpena
// 2026-06-02 (see memory flcc-ignorable-states).
var flccIgnorableStates = map[string]bool{
	"rma":    true,
	"broken": true,
	"debug":  true,
	"dev":    true,
}

// flccIgnorableWorkflow is the FLCC workflow whose nodes are ignored.
const flccIgnorableWorkflow = "broken-collect"

// classifyFLCC buckets one FLCC observation. failed (state=="fail") and
// ignorable are certain; success requires a configured successState; all
// else is in-progress. fail takes precedence over ignorable so a freshly
// failed node is captured before an operator moves it to broken (which
// would later read as ignorable).
func classifyFLCC(obs lifecycleclient.FLCCObservation, successState string) ctOutcome {
	switch {
	case obs.State == "fail":
		return outcomeFailed
	case flccIgnorableStates[obs.State] || obs.Workflow == flccIgnorableWorkflow:
		return outcomeIgnorable
	case successState != "" && obs.State == successState:
		return outcomeSuccess
	default:
		return outcomeInProgress
	}
}
```
