The logical movement of a canary, not the call graph. Start at “Macro flow.” A run is born when an operator adds racks; the system enriches it with discovered facts, then the engine walks the template — it runs every probe_type step it knows how to run (today: alert_baseline and fact_baseline, both gatherers), skips action.tool-shaped steps, and halts at the first operator-gated step (evidence_review). What happens after “add racks.” The green box runs today: POST /api/runs creates the run, discovers facts, then tail-calls engine.Kick — an async goroutine that walks the template, running every probe it has registered (alert_probe, fact_probe) and skipping action.tool-shaped steps until it hits an operator-gated step kind (review / ai_assess / signoff). A healthy walk ends parked at evidence_review; the amber box is iter-4d+ (operator-advance endpoint, real checkpoint evaluator, assertion probes, sign-off).

The canary itself — 14 ordered steps (templates/firmware-release-canary.yaml v4). Steps 1 and 2 (alert_baseline + fact_baseline) run today — both gatherers, captured as evidence. Steps 3–11 are action.tool-shaped, so the engine skips them (no probe wired) and continues the walk. Step 12 (evidence_review) is the first operator-gated step (kind: review) — the walk halts there until an operator-advance endpoint exists (iter-4d).

How the walk actually runs (live, iter-4c). Kick spawns a goroutine on a background context; runOnce is a loop that, on each iteration, re-reads the event log (persistence is truth), picks the next runnable step via findNextRunnableStep, and routes on its kind: halt at review/ai_assess/signoff, skip action.tool-shaped probes (no probe_type), or run a registered gatherer. A probe error → StepFailed and the loop continues (observability framing); a DB read/write failure halts the walk.

The verdict path — planned (iter-4d+). alert_probe and fact_probe are gatherers (evidence, no verdict). The remaining steps will be assertion / action probes: they’ll run action.tool and evaluate a per-rack checkpoint (success_when / fail_when / blockers) into a verdict that rolls up into run status. Needs the checkpoint expression evaluator.
